# 개발 및 검토 절차

## 역할

- **작성자:** `requirements.md`와 기존 코드를 확인한 뒤 `src/actions.py`만 수정합니다. 변경 이유와 변경한 파일을 `workspace/change.md`에 기록합니다.
- **검토자:** 코드를 수정하지 않습니다. 요구사항 충족 여부, 허용된 변경 범위인지, 실제 검사 기록이 있는지를 검토해 `workspace/review.md`에 기록합니다.

## 순서

1. 작성자가 변경하고 `workspace/change.md`를 작성합니다.
2. 작성자는 `python3 -m unittest discover -s tests -v`와 `python3 demo.py`를 실제 실행해 결과를 남깁니다. 검토자는 요구사항, 변경 범위, 실제 검사 기록을 검토하고 `workspace/review.md`에 판정과 근거를 기록합니다.
3. 검토가 통과하면 사용자에게 최종 확인을 요청합니다.
4. 검토가 실패하면 작성 단계로 돌아갑니다. 추가 수정은 최초 변경 이후 최대 2회까지 허용하며, 매 회차의 변경 이유와 파일 및 검사 결과를 기록하고 다시 검토합니다.
5. 두 번의 추가 수정 뒤에도 검토가 실패하면 실패 이유와 권장 다음 조치를 `workspace/review.md`에 기록하고 작업을 중단합니다.

검사를 실행하지 않았다면 그 사실을 명시하고 통과로 판정하지 않습니다.
